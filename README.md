# REST API for a restaurant.


All functionality of the API require a logged in user.

# Users of the system must be able to register and login:
- At a minimum, the system support password based authentication.
- Users must always have a name and email

# This API needs authorization support for two roles namely Administrators and Customers.

# Adminstrators are able to take the following actions:
- To Create, View, List, Update and Delete dishes.
- Dishes always have a name, description, price and image.

# Customers are able to take the following actions:
-  To Search, View and Rate dishes.
- A dish can only be rated once per customer and the rating can be updated.
